**Version 1.9.1 (10/10/2026)**
--------------------------------------

The quit shortcut no longer sits under a face button.

**Fixed — 1**

**Input**
- **The quit shortcut is now L1 + R1 + Start + Select by default.** It was L1 + R1 + A, and a face button is far more likely to be handed to you by a game than the two bumpers with Start and Select are — quitting a session mid-play is not something anyone means to do. Only fresh installs move; a binding you have set yourself is left exactly where you put it.

**Version 1.9.0 (09/10/2026)**
--------------------------------------

ArtMoon now runs on ARM handhelds, and behaves properly under Steam's Game Mode.

**New — 2**

**Platforms**
- **ARM64:** there is now an AppImage for ARM Linux beside the x86_64 one. Both are attached to every release, and both the install script and the in-app updater choose whichever matches the machine they are running on — so an ARM handheld can never be handed the x86_64 file, or the other way round.
- **SteamOS Game Mode:** launched from Steam on a handheld, ArtMoon now opens fullscreen instead of sitting at its default size, and the controller reaches the host. Steam's Game Mode compositor never gives the stream window keyboard focus, so every pad event was being dropped before this.

**Good to know — 1**

**Platforms**
- The ARM64 build needs glibc 2.38 or newer, so it is aimed at SteamOS and other current ARM distributions rather than older ones. PyroWave is not built for ARM.

**Version 1.8.1 (07/10/2026)**
--------------------------------------

Sharing a device now works the first time, and keeps working.

**Fixed — 10**

**Input**
- **Windows:** a device Windows reports as in use can now be shared. Ticking a drive or a keyboard whose own software had claimed it did nothing at all — the bind was refused quietly, and the switch then looked as though it had worked. It is now bound with the force the sharing tool provides, so the device goes where you asked it to go.
- **Windows:** a device you had switched on is now recognised as switched on. The sharing tool reports a forced bind as `Shared (forced)`, and that read as *not shared* — so a device you had lent out still looked available on this machine, and the far machine's copy was never released when the stream ended. Both of those follow from reading it correctly.
- **Windows:** sharing a device no longer fights Razer's software. With Synapse running, a shared Razer keyboard or mouse flapped — taken and handed back every couple of seconds — while every log said the take had worked. The engine's own programs are now moved aside for the seconds the device is attached, and started again when it comes back. Razer's services are never touched.
- **Windows:** the sharing helper now installs and starts reliably. Removing and reinstalling in one step could leave a service marked for deletion and the helper missing altogether; it now retries, waits for the sharing engine before starting, and asks Windows to bring it back if it ever stops.
- **Windows:** the helper's service path is no longer left unquoted. That path contains spaces, and an unquoted path in a service definition is the well-known way for another local account to get its own program run with that service's rights. It is now written quoted.
- **Linux:** the sharing port opens as the stream starts rather than waiting for the far machine to reach it first, so a device can be taken as soon as the stream is up.
- **Linux:** the sharing service is running after a restart. It used to wait for the app to be opened, so a machine that had just been rebooted could not offer anything until somebody had launched ArtMoon on it.
- **Linux:** ArtMoon no longer fights a sharing daemon the distribution already provides. Where one was installed, both started at the same moment, one took the port and the other restarted endlessly; ArtMoon now steps aside when the system's own is present.

**Settings**
- A device you switch on is remembered by the device itself rather than by the socket it happened to be plugged into, so a drive that is unplugged and put back comes back offered instead of needing to be switched on again.
- The device list no longer stops looking once everything is switched off, and a switch left on a device that is not plugged in is kept rather than dropped.

**Good to know — 3**

**Input**
- **Input:** device sharing needs an **[ArtLight](https://github.com/onaiaku/ArtLight) host (V1.5.0 or above)** at the far end. ArtLight is the half that receives the device; other hosts are not supported yet.
- **Input:** device sharing works over a **local network or a VPN, and nowhere else in this release**. The app opens the port only for the machine it is serving, and only while a stream is running.
- **Input:** device sharing is **not behind any authentication at this time** — no password, no pairing step, no account. A device you switch on is offered to whatever can reach the port. Keep both machines on the same network or on a tunnel, and do not expose this port to the internet.

**Version 1.8.0 (05/10/2026)**
--------------------------------------

Your own keyboard and mouse, inside the stream.

**New — 2**

**Settings**
- **Input:** a new USB devices section lists the USB hardware plugged into this PC — name, vendor and bus id — and says of each one whether it is currently offered to another machine over the network. This is the groundwork for sending your real keyboard and mouse into a stream, which is what gets input into a game that ignores ordinary streamed input: nothing is injected, because the game is talking to the physical device. It is not limited to input devices — any USB device can be shared, and a USB drive has been verified end to end, browsed and copied from on the far machine as though it were plugged into it. You will find it under Settings, Input.
- **Input:** every device in that list has an Off/On switch for sharing it. Turning one on hands that device to the machine you are streaming from, and it is gone from this one until the stream ends. Sharing needs the input service — a small privileged piece that arrives with this build: the Windows setup installs it, and on Linux ArtMoon places it itself the first time you need it, with a single password prompt. Until it is in place the switches are shown greyed with the reason written beside them, so nothing here can look as though it worked when it did not. Nothing is shared until you turn something on; the list on its own changes nothing about your devices.

**Good to know — 3**

**Input**
- **Input:** device sharing works with an **[ArtLight](https://github.com/onaiaku/ArtLight) host**. The machine you stream from has to be running ArtLight, which is the half that receives the device — other hosts are not supported at this time.
- **Input:** device sharing works over a **local network or a VPN, and nowhere else in this release**. Reaching it across the open internet is not supported yet — that is the next piece of work, not an oversight. Keep the two machines on the same network, or on a tunnel, and the app opens the port only for the machine it is serving and only while a stream is running.
- **Input:** device sharing is **not behind any authentication at this time**. There is no password, no pairing step and no account — a device you switch on is offered to whatever can reach the port. That is the reason for the limit above, and the reason it should not be exposed to the internet. Authentication is planned; until it is here, treat this port the way you would treat any other unprotected service on your network.

**Under the hood**
- The device list is read from the sharing tool's own output on each platform, with the parsers pinned against captures taken from real machines so that a change in either format cannot pass unnoticed.
- The USB/IP engine ArtMoon needs in order to export a device now ships inside both installers instead of being assumed present. The Windows setup carries usbipd-win behind a Device sharing box that is ticked by default, and the Linux AppImage carries the `usbip` client along with the library it links against. A machine that has never had either can share a device without first being sent off to install something.

**Version 1.7.2 (02/10/2026)**
--------------------------------------

PyroWave works on Windows now.

**Fixed — 3**

**Streaming**
- **Windows:** PyroWave can now actually be selected and used. It needs the GPU renderer, and that renderer was failing to start on every Windows machine with an invalid-argument error, after which the app quietly fell back to the other renderer for the rest of the session. PyroWave is the one codec with no second path on Windows, so it was the only thing that could not survive that fallback, and the app blamed your graphics driver for it. The driver was never at fault and neither was the card. If you tried PyroWave on Windows before now and concluded your GPU could not do it, please try it again.
- **Windows:** choosing Force software decoding while PyroWave is selected no longer leaves the stream running on the graphics card. PyroWave decodes on the GPU and has no software decoder, so those two settings cannot both be honoured. The app used to note the contradiction in a log line and then build the GPU path anyway, so the setting looked as though it had simply been ignored. It now says so plainly and uses H.264, which does decode in software, exactly as it already did for a host that does not support PyroWave.
- **Windows and Linux:** the codec check that runs as a stream starts now asks about the decoder you actually selected instead of always asking the hardware question. Auto and Force hardware decoding behave exactly as before; this is what lets Force software decoding reach the check at all.

**Under the hood**
- The log no longer announces that a data file was "Found" at its embedded location without checking. A file left out of the resource list reported itself present and then handed the caller nothing, so the only visible symptom was an unrelated-looking failure further down. It now says plainly when a file cannot be found.

--------------------------------------

A crash fix for PyroWave on Linux.

**Fixed — 1**

**Streaming**

H.264, HEVC and AV1 were never affected on any platform, and PyroWave on Windows is unaffected.

**Version 1.7.0 (02/10/2026)**
--------------------------------------

A fifth video codec joins the list: PyroWave.

**New — 1**

**Streaming**
- PyroWave is a fifth option in the Video codec list, beside Auto, H.264, HEVC and AV1. It is built for a wired network with bandwidth to spare: it spends more bits than the other codecs, and in exchange the picture never has to resynchronise, so it suits a link with room to spare and suffers on Wi-Fi or at a low bitrate. Picking it raises the bitrate to a level it is worth using at, because left at the other codecs' setting it looks worse than they do. It only works against a host that supports it — every other host keeps streaming H.264, HEVC or AV1 — and a short note appears when you pick it, so nobody has to guess why the picture changed. Available on Windows and Linux.

**Version 1.6.0 (02/10/2026)**
--------------------------------------

The app can update itself on Linux now, and the second Update button on the brand tab is gone.

**New — 1**

**Linux**
- The app updates itself on Linux. Pressing Update now used to answer that updating from the app was Windows only, and on Linux it could not even find the right file to download, because it went looking for the Windows installer. It now looks for the AppImage on every platform, replaces the copy it is running from, and opens it again. If the AppImage is somewhere you own, no password is asked for at all; if it is in a system folder it asks for your password. If you dismiss that prompt, or the copy fails, nothing is changed: the old copy is left exactly where it was and still opens, so you cannot be left without the app. The copy it replaced is kept next to it as a fallback.

**Fixed — 1**

**Interface**
- The brand tab had an Update now button of its own, left over from when that tab was the only place a stale build showed up. It opened the same updater the About tab opens, so having two was one too many, and the About tab's is the one that remains. The version readout and the changelog link on that tab are untouched.

**Version 1.5.0 (28/09/2026)**
--------------------------------------

The last session is back on the home card, the card can stop a stream as well as start one, and the AppImage in this release is the one that starts on older systems.

**New — 2**
- Home shows how the last session on that host went, under the host's link speed: when it ran, how long for, the grade the host gave it, and the RTT, host latency and drop rate it measured. The RTT caption carries the session's peak beside the average. This was on the card before the home screen was redesigned and it is back by request, so it describes the last session on the host — which may have been another device's. Anything the host never measured is drawn as a dash rather than a zero it did not report.
- Stop a stream from the home card. When a session is running on that host, the card now offers Stop under Resume — so a stream can be ended from here and not only started or rejoined. It asks before it does it. A session the host says was started by another device cannot be stopped this way; the host refuses it and its message explains that.

**Fixed — 2**
- The AppImage now starts on older systems. It had been built on a base new enough that it needed a newer C library than Ubuntu 22.04 and Debian 12 ship, so on those machines it would not start at all. It is now built against the oldest still-supported Ubuntu release, so it runs there and on everything newer — which is what a portable build is for.
- The host metrics heading in the stream overlay did not match the same heading in Settings. The two are built in separate places and had drifted apart; they agree again.

**Version 1.4.0 (27/09/2026)**
--------------------------------------

The 25 September library merge, plus everything shipped since. A line is the desktop app unless it says Android.

**New — 30**

**Library**
- The host page splits into Games, Apps and All. All opens first, so desktop, Big Picture and the host's own apps are one list rather than a tab away.
- Move an entry between Games and Apps with the right stick click (M on the keyboard). The choice is kept per host.
- Pinned games: Start on the pad or P pins the selected game, which then sits under Last played in alphabetical order.
- Resume from Home: a host that is streaming shows the game in progress, with Resume in place of Play again.
- The host page reopens on the tab you last chose, per host. A Remote Monitor still in use still opens on Apps.
- Apps show Open, with no hours and no session count. The badge on Home reads "Last played 2 h ago · 18 h total" instead of "Last played for 18 h", which read as though that were the last session.

**Power**
- A row per machine — the host and this device — each offering only what it really supports: Keep on, Sleep, Restart or Shut down.
- Windows updates are offered on the row that restarts or shuts down, and only when that machine has updates waiting.
- A host put to sleep stays asleep until Wake is chosen, so switching this device back on no longer wakes the host with it. Its card reads "Asleep" meanwhile.
- Sleeping a host that could not be woken again warns first — away from home over Tailscale, or with its adapter not set to wake it.
- X is "Power" in the status bar, not "Shutdown".

**Settings**
- Host profiles and per-game settings live on the tabs of Settings, one section at a time, switched with LB / RB, each tab showing how many values it changes.
- An inherited value says where it comes from (Global: 4K, Docked 4K: 120). Y gives one row back; Reset all gives the whole set back.
- Profiles switch with LT / RT from anywhere in the dialog. Per-game settings open with the game's cover and name the profile they inherit from.
- A profile can be named with the pad: X offers eight ready-made names such as Docked, Portable, Handheld and TV, with a field of your own when a keyboard is at hand.

**Interface**
- Card opacity per host — 70% to 100%, starting at 90%, in the host's Background.
- The moving background: waves in the accent colour over the lower three quarters of Home, Settings and the PIN pad, twice as fast while a host is streaming or a launch is starting. Off with Reduce animations, paused over a dialog or a window move.
- An opening animation, about three seconds and skippable with any button: the waves rise, the mark fades in, a band of light writes the name. Settings → Session turns it off.
- The splash wordmark and the window mark are ArtMoon's own, and wording is hosts and this device, not PCs.

**Streaming**
- Shared clipboard: text copied on the host pastes here, and the other way round, up to 32 KB, over a key that lasts one stream. Off until it is turned on, and the host can refuse from its own switch.
- Text marked by a password manager stays out of the other side's Win+V history and is cleared when the original is, within 60 seconds.
- Button prompts: Auto, Controller or Keyboard & mouse, in Settings → Session. Pinning them to the controller suits pads that send clicks and keys from one device, such as Steam Input or a Steam Deck.
- Remote Input and Remote Monitor open beside a running game without asking to quit it, and skip the wait for a game window.
- Host actions report what they did rather than an error — Disconnect Monitor, Disconnect Input, Terminate — and a host asking for confirmation gets Yes or No.
- Less GPU work on 4K: where one device decodes and renders, frames are shown directly instead of being copied first. 1080p and 1440p are unchanged.
- Engine and protocol brought level: faster recovery from lost video packets, the decoder chosen by GPU vendor and driver, audio latency held to 50 ms whatever the packet size, and the latest host discovery library. The client sends its own ID to hosts instead of a placeholder shared by every client.
- Home no longer offers the Internet Hosting Tool.
- Updates come from ArtMoon's own releases, and a waiting update is offered on startup instead of only being found in Settings.

**Android**
- The hero card's LAST SESSION panel matches the desktop: the RTT peak caption ("11 peak"), the grade pill in the host's own colour, and the covers of the games the session credited — a name tile where a host has no cover, "+N" when more games were played than the card shows.
- The app picker sits on the focused app's cover art, blurred and veiled behind the whole list, crossfading as the selection moves. The list and detail panel are translucent over it, and the art runs full-bleed from behind the header, with the main-screen buttons at their original size.

**Fixed — 6**
- Prompts return to the controller's icons as soon as the stick or a trigger is used, not only on a button press, and show them from the first screen when a controller is connected.
- Resume no longer waits behind the launch screen. With "Wait for the game to appear" on, rejoining a game the host was already running could hold the launch screen over a picture that was ready.
- Pointing at a game with the mouse updates the cover and details beside the list, not only the highlight on the row.
- A host running Tailscale could be recorded with its Tailscale address as its local one, and the log then reported it moving back to the LAN every few seconds.
- The software renderer drew full-range video at the wrong levels, a display larger than 8K could crash the display list, and a game with an empty name stopped the whole library from loading.
- Android: lost video packets are reported again, so a stream recovers from a bad moment instead of carrying it.

**Version 1.2.5 (21/09/2026)**
--------------------------------------

**New — 1**
- Linux: an on-screen keyboard for handhelds. The Qt Virtual Keyboard is now bundled into the AppImage and renders inside ArtMoon's own window, which is the only form that can be relied on fullscreen under gamescope on a Steam Deck, where a second top-level window has no window manager to place it. **Version 1.2.0 (04/09/2026)**
--------------------------------------

**New — 1**
- Android client joins the family: our rebranded fork of Moonlight Android now ships signed alongside the Windows installer and Linux AppImage (ArtMoon-1.2.0-android.apk). Built by CI on every v* tag, signed with the same release keystore, minSdk 21 (Android 5.0+). Consolidated into this repo as /android on 2026-09-07.

**Fixed — 3**
- Linux AppImage: the bundle no longer carries its own copy of the glib family (libglib, libgobject, libgio, libgmodule, libgthread). The 1.1.1 bundle's glib was older than the host's and missing the g_string_copy symbol, so libva driver plugins — notably nvidia_drv_video.so, which links glib — failed to dlopen inside the AppImage, and SDL reported "Failed to initialize VAAPI: -1" (the "no functioning hardware accelerated video decoder" dialog) on every NVIDIA host. The host's glib is now always used, restoring hardware decoding on NVIDIA. A CI hard-check now fails the build if any glib library is ever bundled again, same as the existing libvulkan check.

- AV1 Vulkan "brick" artifacts: root cause found and fixed. CI compiled FFmpeg with link-time optimization (LTO), which miscompiled FFmpeg's Vulkan hardware decode path — the direct cause of the recurring AV1 corruption on RTX 50-series hosts. CI now builds FFmpeg with the exact flag set proven clean over days of A/B graft testing: no LTO, debug symbols stripped, full hardware-acceleration set enabled. The fixed build streams AV1 10-bit HDR with zero artifacts.

- CI now verifies the packed artifact itself (not just the staging directory) before shipping: the final AppImage is extracted and inspected for the glib family and a bundled libvulkan, so neither class of silent regression can ever reach a release again.

**Changed — 2**
- The bundled FFmpeg is now 9.0.1 (previously 9.0), pinned to the exact decoder build verified clean on the RTX 5060 mini PC at up to 138 FPS in 4K 10-bit HDR.

- The settings store is now named ArtMoon, in the config directory and the Windows registry key alike. On first launch, 1.2.0 migrates every existing setting to the new store automatically — nothing is lost, no re-pairing, no reset notice. The old store is left untouched so a downgrade to 1.1.x still works.

**Version 1.1.0 (02/09/2026)**

**Fixed — 1**
- Linux AppImage: the bundled libplacebo was built without a SPIR-V compiler (shaderc), so Vulkan device creation failed on every GPU and the client could fall back to VDPAU only — no AV1 hardware decoding, and a black window on systems where the fallback also failed. **Version 1.0.0 (01/09/2026)**
--------------------------------------
First public release of ArtMoon — a gamepad-first streaming client for your host gaming PC, built on the Moonlight streaming engine.

✨ FEATURES:

- Gamepad-first interface — built for the sofa and the handheld. Every screen is navigable end to end with a controller, with keyboard and mouse always available alongside. Button prompts follow whatever you're actually holding

- Home at a glance — your hosts as tabs under the wordmark, each card showing its state, its addresses, its link speed and exactly what it would stream at right now: resolution, frame rate, bitrate, HDR, codec and audio, following the active profile

- Host page with a spotlight — one game at a time, shown in full: cover art, full title, store, and the right verb (Play, Resume, Open). The rest of the library sits beside it as a list, with cover art fetched from Steam, GOG, Epic and more

- Per-host profiles — up to three named profiles per host (e.g. a "Docked" 4K/120/HDR profile and a "Handheld" 1080p/60 one), switched from the host list with LB/RB or from the host's own page

- Per-game settings — any game can override resolution, frame rate, bitrate, HDR, codec, frame pacing and audio, so a AAA title launches at 4K/120 while an indie runs at 1080p/60, automatically

- Custom resolutions — any width × height for displays that don't match a preset, including the 16:10 panels on handhelds

- Performance overlay — thirteen lines of live stats (stream, bitrate, frame queue, host GPU/VRAM/CPU/encoder/temperature), built line by line on the overlay itself: position, colour, size, transparency. Minimal / Default / Full presets included

- Live Stream Settings — change resolution, frame rate, bitrate, HDR and frame pacing mid-stream without leaving the game; save to the active profile from inside the stream

- Match refresh rate — optionally runs your display at the stream's frame rate for the session (60 FPS stream on a 120 Hz screen = one frame per refresh), restoring it when the stream ends

- Wake, PIN and power — Wake-on-LAN with a controller-reachable PIN pad for locked hosts, remote shutdown, and remote Windows Update on the host, all from the sofa

- Tailscale-aware — hosts reachable over Tailscale are unified into one tile with both addresses, and the client always prefers the faster local path when it's available

- Configurable shortcuts — every in-stream keyboard hotkey and gamepad combo is rebindable; controller glyphs follow Xbox / PlayStation / Nintendo layouts

- Accent colour — five presets or any hex code; the interface follows it everywhere, while status colours stay meaningful

✨ PAIRED FEATURES (with ArtLight on the host):

Pairing with ArtLight — https://github.com/onaiaku/ArtLight — unlocks the sofa-to-host experience, switched on per host in Settings:

- Link-speed matching — the host matches its wired link speed to this device, so a 2.5 Gbps host feeding a 1 Gbps handheld stops bursting audio packets it can't deliver

- Seamless launch — optionally wait for the game to appear on the host before the stream is shown, watching its cover art instead of its desktop

- Wake the host and sign in with its Windows PIN, from the sofa, on the pad

- Live host metrics overlay — GPU, encoder, VRAM, temperature, CPU and network figures measured on the host itself

- Game library sync with store badges, and the host's last session — quality grade, duration, charts, cover art — on your Home screen

- Remote host power-off and Windows Update

ArtLight is optional: ArtMoon streams perfectly well against any Sunshine / Apollo / Vibepollo / Vibeshine host without it.

🎮 PLATFORMS:

- Windows 10 and 11 (x64). Works against any Sunshine-compatible host

🙏 THANKS:

- The Moonlight team (moonlight-stream) for the streaming engine this client is built on. FFmpeg, D3D11VA, DXVA2, libplacebo and moonlight-common-c do the heavy lifting, and we leave them exactly as they are — our work lives in the interface around them
